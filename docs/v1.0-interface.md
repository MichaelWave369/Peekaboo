# Peekaboo v1.0 map-first interface

Peekaboo v1.0 changes the presentation shell without weakening the acquisition, provenance, uncertainty, and change-ledger contracts established in the v0.x series.

## Design goal

The primary interaction should feel immediately familiar to anyone who has used a modern consumer map:

1. search for a place;
2. inspect the map;
3. open or hide map layers/data controls;
4. scan the current bounded viewport explicitly;
5. select a mapped object for details.

The interface borrows common map-product interaction patterns, not third-party branding or proprietary map styling.

## v1 layout

- The map owns the full workspace instead of being permanently reduced by fixed side columns.
- Address/place search floats over the upper-left map area.
- A menu button shows/hides the Peekaboo research/data sheet.
- The data sheet is an overlay and remains independently scrollable.
- Object details appear as a floating right-side card only after selecting a marker.
- On narrow screens, object details become a bottom sheet.
- Leaflet zoom controls move to the lower-right and use familiar high-contrast map-control styling.
- OpenStreetMap tiles are shown close to their natural color rather than with the earlier heavy dark desaturation filter.
- Peekaboo's lime identity and surveillance-category colors remain intact.

## Preserved semantic boundaries

The visual redesign does not change these rules:

- Place search only navigates. It does not automatically scan surveillance data.
- A scan remains an explicit user action.
- Loaded records remain bound to the viewport that produced them.
- `VIEW MOVED • RESCAN` still distinguishes current map position from loaded evidence.
- Missing OSM records never imply absence of real-world surveillance.
- Flock/vendor identity remains an OSM claim unless independently verified elsewhere.
- Sharded scans remain all-or-nothing.
- Cross-shard payload conflicts reject the acquisition rather than choosing a winner.
- Rate limits, `Retry-After`, endpoint cooldowns, and the per-scan request budget remain enforced.
- Change-ledger states describe OSM record changes, not independently verified physical installation/removal.

## Accessibility and responsive behavior

- The map menu is a real button with `aria-expanded` state.
- The search input retains a descriptive accessible label.
- Desktop users can hide the research sheet to maximize map area.
- Mobile/narrow layouts default to a closed research sheet and use a bottom-sheet object inspector.
- Existing keyboard focus styles remain active across buttons, links, and inputs.

## Product identity

Peekaboo v1 is intentionally map-first and approachable on the surface while preserving the deeper audit and research tools beneath the menu.

**PEEKABOO**  
*Public Eye Explorer for Known Area-Based Observation Objects*  
**See what sees you.**
