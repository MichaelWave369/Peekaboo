# Peekaboo v1.1 context-layer policy

Peekaboo v1.1 adds two **context** filters alongside the existing surveillance-type categories. Context does not replace the original type classification. A Flock Safety ALPR can therefore remain a Flock ALPR while also carrying public-space or park/recreation context when the OpenStreetMap record supports that claim.

## Public space

Peekaboo accepts the following OSM evidence:

- `surveillance=public` — explicit public-surveillance context.
- `surveillance:zone=public` — public-zone context.
- `surveillance:zone=town` — town surveillance context.
- `surveillance:zone=street` — street surveillance context.

The OpenStreetMap wiki notes that `surveillance:zone=public` and `street` can be ambiguous. Peekaboo therefore displays the exact source tag in the object inspector rather than presenting the context as independently verified fact.

**Public-space context does not establish public ownership, public operation, law-enforcement ownership, or current device status.** Operator names are never used by themselves to infer this context.

References:

- https://wiki.openstreetmap.org/wiki/Key:surveillance
- https://wiki.openstreetmap.org/wiki/Key:surveillance:zone

## Park / recreation

The standard surveillance-zone documentation does not currently define a canonical `park` surveillance-zone value. Peekaboo therefore treats park/recreation as a conservative tagged-context layer rather than a standardized camera type.

Peekaboo accepts explicit record-level evidence such as:

- `surveillance:zone=park`
- `surveillance:zone=playground`
- `surveillance:zone=recreation_ground`
- `surveillance:zone=sports_centre`
- `leisure=park|playground|recreation_ground|sports_centre`
- `landuse=recreation_ground`
- `location=park|playground|recreation_ground|sports_centre`

Peekaboo does **not** infer park context from a nearby park polygon, an operator name, or free text such as `name=Central Park Camera`.

This intentionally favors fewer, better-explained matches over a larger layer built from proximity guesses.

## Filter semantics

Type filters and context filters are separate dimensions:

```text
TYPE FILTERS
Flock / Camera / ALPR / Guard / Gunshot / Other
              ×
CONTEXT FILTERS
Public space / Park & recreation
```

Multiple active context filters use OR semantics. Type filtering is applied first, context filtering second, and loaded-record text search third.

## Exports

- GeoJSON exports include the matched context names and evidence objects.
- JSON audit manifests include context counts, active context filters and interpretation language.
- Context filters are preserved in copyable Peekaboo view URLs.

As with every Peekaboo layer, these are claims derived from public OpenStreetMap metadata, not independent verification of physical surveillance infrastructure.
