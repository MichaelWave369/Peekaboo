# Peekaboo v0.8 transport reliability policy

Peekaboo uses public OpenStreetMap Overpass infrastructure conservatively. v0.8 adds explicit endpoint-health and request-budget rules so resilience does not become accidental API abuse.

## Endpoint circuit breakers

Each configured Overpass endpoint has session-scoped health state.

- Ordinary failures such as timeouts create a short **soft cooldown**.
- Adaptive smaller-shard recovery may bypass a soft cooldown because the query shape is materially smaller.
- HTTP `429` and any response with an explicit `Retry-After` create a **hard cooldown**.
- Hard cooldowns cannot be bypassed by adaptive sharding.
- A successful request clears that endpoint's failure streak and cooldown.
- Cooldown state is advisory and session-local; storage failure does not break the scanner.

## Rate-limit policy

HTTP `429` is not a sharding trigger.

If a public endpoint says too many requests, Peekaboo does not reinterpret that response as permission to issue four smaller requests. `Retry-After` is parsed as either delta-seconds or an HTTP date and is respected within a bounded local cooldown.

## Request budget

A single user scan has a hard ceiling of **10 live network requests**, including the initial full-viewport attempt, endpoint failover, and any four-shard adaptive recovery.

Cached reads do not consume the live request budget.

If the budget is exhausted before a complete result can be acquired, Peekaboo aborts the refresh instead of exceeding the ceiling.

## Completeness

Adaptive scans remain all-or-nothing.

- All four shards must complete successfully.
- Shared-boundary OSM records are deduplicated after merge.
- If one shard fails, partial shard data is rejected.
- Previously loaded known-good data remains available in the UI after a failed refresh.

## Audit metadata

The JSON manifest can include:

- endpoint health snapshots;
- skipped endpoints and cooldown reasons;
- request-budget limit / used / remaining;
- network attempts for the current load;
- scan mode (`single` or `sharded`);
- shard details;
- fallback reason;
- endpoint failure history.

These values describe acquisition behavior, not real-world surveillance completeness.
